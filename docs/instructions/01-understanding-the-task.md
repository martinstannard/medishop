# 1. Understanding the Task

Your primary goal is to fully understand the user's request before you begin any work. Misunderstanding the request is the most common cause of errors and wasted effort.

## 1.1. Clarify Ambiguity

If any part of the user's request is unclear, ambiguous, or incomplete, you **must** ask for clarification. Do not make assumptions.

**Examples of when to ask for clarification:**

*   The user asks for a "new feature" without specifying the exact requirements.
*   The user mentions a bug but doesn't provide steps to reproduce it.
*   The user uses vague terms like "make it better" or "improve performance."

**How to ask for clarification:**

*   Be specific about what you don't understand.
*   Provide options or examples to guide the user.
*   Repeat your understanding of the request to confirm it with the user.

## 1.2. Define Acceptance Criteria

Before you start working, define the acceptance criteria for the task. These are the conditions that must be met for the task to be considered complete.

For a new feature, the acceptance criteria should include:

*   The user-facing functionality.
*   Any performance requirements.
*   Any design or UI constraints.

For a bug fix, the acceptance criteria should include:

*   The steps to reproduce the bug.
*   The expected behavior after the fix is applied.
*   Any potential side effects to consider.

Document these acceptance criteria in your plan.
