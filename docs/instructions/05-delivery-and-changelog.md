# 5. Delivery and Changelog

Once you have completed all the steps in your plan, you are ready to deliver your work.

## 5.1. Update the Changelog

Before you deliver your work, you must update the `CHANGELOG.md` file. The changelog is a record of all the changes that have been made to the project.

**Changelog Entry Format:**

Follow the [Keep a Changelog](https://keepachangelog.com/en/1.0.0/) format.

```markdown
### Added

-   New user profile page.
-   `GetUserProfile` endpoint.

### Fixed

-   Bug where the user's avatar was not displayed correctly.
```

## 5.2. Propose a Pull Request

If the project uses a version control system like Git, you should propose a pull request (or merge request) with your changes.

**Your pull request description should include:**

*   A summary of the changes you have made.
*   A link to the relevant issue or task.
*   Any instructions for the reviewer.

## 5.3. Await Review

Once you have proposed a pull request, you must wait for it to be reviewed by a human. Do not merge your own pull requests.

## 5.4. Address Feedback

The reviewer may ask you to make changes to your code. You must address all feedback before your pull request can be merged.
